# easy-command 2.0 版本规划

## 定位

`easy-command` 是一个面向 macOS 与 Ubuntu/Debian 用户的 Zsh 终端初始化工具。目标是在不破坏用户已有配置的前提下，用一条命令完成稳定、可回退的终端环境配置。

本文件仅用于仓库协作和开发跟踪，不纳入 npm 发布包。

## 1.x 当前能力

- 安装 Zsh、Git 及 Oh My Zsh。
- 配置 `agnoster` 主题、Git 状态展示、命令历史建议、语法高亮和原生 Tab 补全。
- 支持指定目标用户、跳过登录 Shell 修改和卸载托管的 `.zshrc` 配置块。
- 修改 `.zshrc` 前自动创建时间戳备份。
- 支持 macOS（Homebrew）和 Ubuntu/Debian（apt-get）。

## 2.0 目标

2.0 不改变“一条命令完成 Zsh 基础配置”的定位，重点解决安装后的可检查、可预览、可修复问题，并将高频效率工具做成可选能力。

### 2.0 包含范围

- 新增安装预览，用户可在修改系统前确认将执行的操作。
- 新增环境诊断，快速定位 Shell、配置块、依赖和插件异常。
- 新增更新与修复能力，安全更新工具管理的仓库并恢复受损配置。
- 提供目录跳转、模糊搜索和常用 Git 快捷操作等可选效率增强。
- 完善自动化验证和发布前检查，确保升级不会破坏现有用户配置。

### 2.0 不包含范围

- 不改造为通用包管理器或完整开发环境管理平台。
- 不强制安装 `fzf`、`zoxide` 等非基础依赖。
- 不覆盖或格式化用户自行维护的 `.zshrc` 内容。
- 不一次扩展大量 Linux 发行版；先保证 macOS、Ubuntu/Debian 的稳定性。

## 2.0 功能规划

### P0：安全与可诊断性

#### 安装预览

新增 `--dry-run` 参数，仅展示而不执行以下操作：

- 将安装的系统依赖。
- 将克隆或更新的 Oh My Zsh、自动建议、语法高亮插件。
- 是否修改默认登录 Shell。
- 将写入 `.zshrc` 的托管配置块。

验收标准：`--dry-run` 不创建目录、不修改文件、不执行 `sudo`、不变更登录 Shell。

#### 环境诊断

新增 `easy-command doctor`，检查并以成功、警告、错误区分输出：

- 当前 Shell 是否为 Zsh，以及默认登录 Shell 是否已切换。
- `.zshrc` 中的托管区块是否完整且仅存在一份。
- Oh My Zsh 和两个插件目录是否存在、是否为可用 Git 仓库。
- `zsh`、`git` 等必需命令是否可用。
- 使用非交互 Zsh 加载配置时是否出现错误。

验收标准：每条异常都有明确的修复建议；诊断本身不修改用户环境。

#### 修复与更新

新增以下命令：

- `easy-command repair`：重新检查依赖与托管配置，缺失时恢复；写入前仍创建备份。
- `easy-command update`：更新工具管理的 Oh My Zsh 和插件仓库，并重新写入当前版本的托管配置。

验收标准：重复执行安全；不删除用户自己的 Zsh 配置、插件或历史记录；失败时保留原有可用配置。

### P1：终端效率增强（可选）

#### 目录快速跳转

支持通过参数启用 `zoxide`。安装后可使用 `z <关键词>` 跳转至常用目录。

#### 模糊搜索

支持通过参数启用 `fzf`，增强历史命令搜索和文件/目录选择。默认保持 Zsh 原生体验，不强制安装。

#### Git 快捷操作

提供一组可选的、命名清晰的 Git 别名，例如状态查看、暂存、提交、拉取、推送和精简日志；不得覆盖用户已定义的同名别名。

验收标准：每项增强可单独启用或关闭；启用前检测冲突并提示用户，不静默覆盖已有配置。

### P2：兼容性与文档

- 补充 Apple Silicon、Intel macOS、root 执行后指定普通用户等场景验证。
- 补充网络异常、无 `sudo` 权限、受损 `.zshrc` 标记等错误处理测试。
- README 增加升级、诊断、修复、回退、可选组件和常见故障说明。
- 评估新增 Arch、Fedora、WSL 支持的投入；仅在有可验证的安装流程后纳入后续版本。

## 2.0 实施顺序

1. 整理安装器内部命令分发，使安装、诊断、修复、更新共用安全检查与备份逻辑。
2. 实现并验证 `--dry-run`。
3. 实现只读的 `doctor`。
4. 实现 `repair` 和 `update`，覆盖失败回退与重复执行场景。
5. 增加 `zoxide`、`fzf`、Git 快捷操作的独立可选开关。
6. 补齐 README、脚本测试和发布前检查。

## 2.0 发布验收

- 新安装、重复安装、`--no-chsh`、`--uninstall`、`--dry-run`、`doctor`、`repair`、`update` 均通过对应环境验证。
- `.zshrc` 中非托管内容在所有操作前后保持不变。
- macOS 与 Ubuntu/Debian 至少各完成一次干净环境验证。
- `npm pack --dry-run` 仅包含预期发布文件，且不包含本规划文档。
- `package.json`、`install.sh`、README 的版本号和安装示例一致。

## 后续方向

目标：让安装、重复执行和卸载在常见环境中可预测、可诊断。

- 为 macOS、Ubuntu/Debian 的首次安装、重复安装、`--no-chsh`、`--uninstall` 建立脚本测试场景。
- 补充网络不可用、缺少 `sudo`、不存在目标用户、依赖安装失败等错误提示的验证。
- 明确重复执行时各个 Git 仓库的更新策略，避免配置已更新但插件版本长期滞后。
- 检查 `.zshrc` 中托管区块异常缺失结束标记时的保护与恢复行为。

验收标准：失败时不留下半写入的 `.zshrc`；重复执行不会产生重复托管区块；卸载只删除本工具写入的内容。

2.0 完成后，再依据真实使用反馈评估主题选择、更多系统支持、开发环境检测等能力，避免在首个大版本中扩大维护范围。

## 变更原则

- 优先保持安装器可重复执行和可回退。
- 不覆盖 `.zshrc` 中非 `easy-command` 管理的内容。
- 不新增依赖或配置项，除非能解决明确的兼容性或体验问题。
- 未经明确确认，不修改版本、不执行发布、不改变 npm 发布文件清单。
